# 可编辑资产包生成与恢复

适用于资产包单独任务，以及 full-video 的最终交付。先定义用户要能复用到什么程度：仅二次剪辑、修改字幕与旁白，还是可重渲镜头。按约定收集，不自动要求所有环境拥有同一套生成工具。

## 1 确认最终版本

读取成片、脚本、时间轴、音轨和工程版本，明确哪些是实际用于最终输出的文件，哪些是被弃用的草稿。把最终主片当可核验参考，不凭文件名含“final”认定版本。

比较已有包的文件清单与本次需要，恢复缺项；如果主片已经通过且只要求打包，不重新生成视频或配音。

## 2 准备可复用内容

按 [目录模板](../templates/acceptance-and-delivery.md) 建立独立 staging 目录，不在用户源文件上原地改名和删除。

包含约定的主片、适配预览、人声与最终音轨、字幕、封面、标题文案标签、事实来源、分镜、实际可编辑工程、模型或原创资产、依赖及许可。固定参考声只有在需要且可合法交付时才加入。

按[观众文案与必要披露](quality-and-delivery.md#观众文案与必要披露)区分发布介绍和技术文档：面向观众不主动添加 AI 制作说明，工程 README 保留必要工具、依赖、声音来源、许可及复现步骤；不要为包装文案偏好返工已验收主片或清除溯源信息。

以下内容需要专门核对：

- 代码引用的是包内相对路径；不能遗留工作机绝对路径、私有链接和凭据
- 代码读取的模型、材质、字体与时间轴是当前成片对应版本，不能把仅“看起来相似”的旧资产当最终源文件
- 字体子集可能只覆盖当前文案，README 要说明改字后的补字方式及许可
- 外部模型或素材仅在许可允许时随包交付；只能成片使用的原始素材改为来源及取得说明
- 不必附巨大模型权重或缓存；没有它们时能做哪些修改、哪些需要重新准备环境，应写清楚

如果需要将素材转换为交换格式或精简几何，先保留原文件，在实际使用路径上渲染代表帧或比较关键属性，记录转换差异。不能只看导出命令成功就说精确复现。

## 3 验证可编辑性

在隔离工作目录按 README 重新打开或运行最小相关操作，例如加载场景、读取字幕、渲染代表帧或重新混合既有人声。选择能证明用户所需复用能力的检查，避免无必要整片重渲。

记录实际检查的范围。仅打开工程不等于已完全复现视频；缺环境时保留完整材料并说明尚未验证的部分，不悄悄安装或使用未批准的本地额度。

## 4 建清单和打包

可使用已有项目打包脚本，先阅读其路径与排除规则。没有现成脚本时，标准库命令示例；执行前确认输出是本轮的新版本路径，不能覆盖用户已有包：

```sh
# 在项目输出目录执行，assets 是准备好的交付目录
python <skill目录>/scripts/asset_manifest.py create \
  --root ./assets --output ./asset-manifest.json

python <skill目录>/scripts/asset_manifest.py verify \
  --root ./assets --manifest ./asset-manifest.json --strict

python -m zipfile -c ./完整创作包.zip ./assets ./asset-manifest.json
python -m zipfile -t ./完整创作包.zip
```

`<skill目录>` 是本环境实际 Skill 路径的占位，执行前替换；不要把示例当已运行记录。清单位于 assets 外，ZIP 包含 assets 和清单，避免自引用。ZIP 自身再记录字节数及 SHA-256 于包外交付记录。

打包后检查成员列表及 CRC。对约定的用户下载路径进行完整回读，重新检查 ZIP 哈希和解压后文件清单；只检查云端原文件不能证明下载文件无损。

## 5 交付与恢复

分清主片和聊天预览用途，保持主片质量；必要时重新编码小预览，实际验证当前渠道，不猜固定文件上限。给 README 和文件用途，不要求用户为了看成片安装运行环境。

包打不开时检查下载完整性、哈希、ZIP 结构、文件名和解压工具表现；有证据后修复，不简单把“打包成功”作为答复。缺项或损坏只修复受影响部分，重新生成对应清单与包版本。

本地素材库入库继续走 [本地 adapter](local-codex-library-adapter.md)。上传、公共分享、发布和本地清理分别依当前授权。完成后在本轮报告中记录实际检查与可复用问题，再进入 [自进化检查](self-evolution.md)。
