# 抖音竖屏科普质量标准（质量门槛）

默认对每条视频生效，除非用户在本次明确改写某一项。分镜、有声样片、成片三个阶段都要逐项对照；任一硬性项失败即阻断交付和上传，回到对应阶段返工。“自动”项用 `scripts/quality_check.py` 测量，“人工”项须看实际画面或听实际音轨后逐条记录，不能凭代码或静帧标通过。

数值是经验起点（来自对科普爆款的公开研究与本流程旧片的问题诊断），不是平台官方规则，也不保证流量。用户明确更改时，记录改动及理由。

## 硬性项

| 类别 | 要求 | 检查 |
| --- | --- | --- |
| 格式 | 1080×1920，30fps | 自动 |
| 首帧 | 第 1 帧即有意义的运动画面；无黑场、淡入、静止标题卡或截图卡 | 自动（首帧亮度、首秒帧差）+ 人工 |
| 钩子 | 0–3 秒内：运动中的冲突或反差画面 + ≤12 字超大标题 + 一句与观众相关的问题；口播首句 ≤2 秒进入问题 | 人工 |
| 镜头长度 | 目标 2–3 秒，均值 ≤3.5 秒，单镜头 ≤5 秒；超过须在分镜写明理由（如关键数字停留） | 自动（场景检测+分镜时间） |
| 镜头密度 | 每 60 秒 ≥20 个不同镜头；每句旁白至少一次画面变化 | 自动 + 分镜 |
| 场景复用 | 同一场景同一机位累计 ≤约 6 秒；再次使用须换机位、焦段或状态 | 人工（分镜） |
| 运动 | 镜头有推拉、对象动作或切换；全片帧差均值 ≥3.0（360 宽分析，YDIF） | 自动 |
| 灯光 | 3D 镜头使用主光/补光/轮廓光、景深和 HDRI 反射；主体与背景分离 | 人工 |
| 色彩 | 每段有主色变化，不全片单一色调；平均饱和度 SATAVG ≥28；明暗跨度 YHIGH−YLOW ≥120（软性） | 自动 + 人工 |
| 字幕 | 粗体无衬线 ≥64px（1080 宽），带描边或底，关键词高亮；位于安全区（避开顶部约 10%、底部约 20%、右侧约 12%） | 人工（手机尺寸截图） |
| 屏幕文字 | 不用手机上读不清的细小信息条、来源条、时间轴；任何字 ≥48px，重要数字做全屏大字 | 人工 |
| 声音 | 全程 BGM，人声时 ducking；切镜与文字弹出配 SFX；整体 −14 LUFS ±1，真峰值 ≤−1 dBTP；不得只有人声 | 自动（响度、峰值、静音间隙启发式）+ 人工 |
| 许可 | BGM/SFX 来自免费可商用来源，记录来源、许可与署名要求 | 人工（素材清单） |
| 结尾 | 明确的收藏或评论触发（如“收藏备用”理由、一个值得回答的问题），不以信息卡收尾 | 人工 |
| 封面 | 最强画面 + 3–8 字大字（问题或反差），可加系列编号；缩略图可读 | 人工 |
| 标题 | 疑问或反常识句式 + 具体对象，≤20 字，不夸大，正文兑现 | 人工 |
| 系列与来源 | 固定系列名/IP 视觉（片头短标识、配色或结尾句）；片中或简介标注参考来源 | 人工 |

## 三个阶段怎样过门槛

1. **分镜**：在 storyboard.csv 中逐镜头写时间、机位、主色、字幕字号与位置、BGM/SFX 点；用 `--storyboard` 检查镜头长度和密度；人工项逐条写“满足方式”。不过门槛不渲染。
2. **有声样片**：对样片运行 `quality_check.py`，并看手机尺寸截图确认字幕、钩子和灯光。不过门槛不扩全片。
3. **成片**：对最终编码文件运行 `quality_check.py`（有 BGM 分轨时加 `--bgm-stem`），生成每秒 1 帧的接触表自查；JSON 结果和人工逐项记录放项目工作区。自动硬性项全部 pass 且人工项全部记录通过后，才能交付或上传。

## 测量的局限

场景检测漏判溶解转场、误判快速运动；静音间隙启发式只能说明是否存在连续音床，不能识别是否是音乐；饱和度与帧差是全画面平均值。测量值与观感冲突时以实际看听为准，但不能用主观判断放宽硬性项，只能修片或经用户明确同意改标准。
